Amazon Developer Hackathon 2026 · Fire TV

Friction log

What we tried with Fire TV, Login with Amazon, and the surrounding tools, what we expected, what actually happened, and what would have unblocked us. The game itself is at www.d20fireverse.it. Source notes live in the repository at docs/FRICTION_LOG.md.

Restart the table server

Medium 28 September 2026

Task
Run the table server on the VPS.
Steps
npm run start, listening on port 3100.
Expected
A clean boot after a restart.
Actual
EADDRINUSE, and the process died with exit 137 while the port was still held.
Workaround
fuser -k 3100/tcp before start. Written into the local dev notes.
Suggestion
A Fire TV sample for one WebSocket server on one port should include the restart, not only the happy path.

Second attack on the Fire TV remote

High 28 September 2026

Task
Attack a second enemy after the first kill, using the remote.
Steps
Attack the first foe, then press OK on the next one.
Expected
A second attack, or a clear reason why not.
Actual
The action was already spent, and the press was read as a move onto the enemy. The fight felt stuck.
Workaround
End Turn. Later, OK on an enemy means strike, and a first-fight coach marks the recommended action.
Suggestion
Remote samples should show that OK confirms the focused action, and that a spent action stays visible. A game cursor is not a mouse click.

Speech from the Fire TV remote

High 28 September 2026

Task
Speak a command into the Fire TV remote microphone.
Steps
Look for speech-to-text inside the Fire OS WebView.
Expected
The remote mic produces a transcript the game can turn into a move, an attack, or end turn.
Actual
The WebView has no speech-to-text. The remote cannot talk to the app.
Workaround
The phone is the second seat. It scans the TV's QR code and sends structured intents. The die is thrown on the phone and lands on the television.
Suggestion
Document whether the Fire TV remote microphone is available to third-party apps. If it is, publish a WebView sample. If it is not, say so on the track page.

Room lights from game state

High 28 September 2026

Task
Change the room lights when the scene changes.
Steps
Look for an API a third-party app can use to trigger the customer's Alexa-linked lights.
Expected
The same server state that rolls the die can set the room.
Actual
There is no public API for a third-party app to command the customer's devices.
Workaround
The feature was cut. The game is fully playable on screen, remote, and phone.
Suggestion
A permissioned, per-household trigger, a routine or a narrow lighting scope, that an app can call without owning the customer's whole account.

The Stick kept an old build

Low 28 September 2026

Task
Serve the TV client as the page the Fire TV app loads.
Steps
Build the PixiJS app and have Express serve tv/dist.
Expected
One URL, always current.
Actual
The Stick keeps the previous build until the client is rebuilt and the server is restarted.
Workaround
Rebuild the TV package, then restart. Day to day we use the Vite dev server.
Suggestion
Say in the WebView docs that a packaged page is a snapshot, and show a cache-busting header for local development.

Login with Amazon in a public repository

Medium 13 October 2026

Task
Compile Login with Amazon from a clean clone.
Steps
Depend on the Login with Amazon Android SDK from Gradle.
Expected
A clean clone compiles the sign-in path.
Actual
The SDK may not be redistributed, so the jar is not in git. The app compiles a stub unless someone downloads the jar by hand. Sign-in stays off until a security profile, client id, and API key exist.
Workaround
scripts/fetch-lwa-sdk.sh and a no-SDK source set. Without keys, the table offers a test account and plays the same.
Suggestion
Publish the SDK where Gradle can resolve it, and add a Fire OS sample that signs in with profile scope and shows the consent-screen privacy URL requirement up front.
